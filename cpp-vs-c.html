C / C++ 入门对比指南

C++ 与 C 的区别

它们流着同一支血脉，却走向了两种思路：C 是一门贴近硬件、讲究“自己动手”的过程式语言； C++ 在 C 的性能地基上，长出了类、模板、异常与 STL 这些抽象工具。 本文用大白话把它们从头到尾比一遍。

01 · 历史渊源：一个是“祖师爷”，一个是“加强版”

C 语言诞生于 1972 年的贝尔实验室，由 Dennis Ritchie 设计， 最初的目的是重写 Unix 操作系统。它需要一门“比汇编好写、又几乎和汇编一样快”的语言， 于是 C 具备了这些特征：贴近硬件、没有运行时包袱、可移植。 1978 年《The C Programming Language》（K&R 版）出版，1989/1990 年出了第一个 ISO 标准（C89/C90）， 之后是 C99、C11、C17、C23。

C++ 则出现在 1979 年，作者是同样在贝尔实验室的 Bjarne Stroustrup。 他要做分布式系统仿真，用 C 写觉得“抽象能力不够”，用 Simula（早期面向对象语言）写又太慢。 于是他动手给 C 加上了类，项目最初就叫 “C with Classes”， 1983 年正式改名为 C++——名字里的 ++ 正是 C 的自增运算符， 寓意“C 的下一代、再进一步”。1998 年 C++ 有了第一个 ISO 标准（C++98）， 2011 年的 C++11 被称为“现代 C++”的起点，之后是 C++14/17/20/23。

一句话记住关系

C++ 是在 C 的基础上“长大”的：语法、指针、数组、编译模型都继承自 C， 但在此之上加了一整套抽象机制。两者是同一个家族的两条分支， 不是“新旧版本”的替代关系——今天 C 依然活跃在操作系统内核和嵌入式领域。

发展时间线速览
时间C 语言C++

02 · 编程范式：C 是“一条路”，C++ 是“多条路”

“编程范式”说白了就是你组织代码的思路：把数据放哪、把逻辑放哪、怎么复用。 这是两者最本质的差别。

C 面向过程（Procedure-Oriented）

  • 程序 = 一堆函数按顺序调用
  • 数据（结构体、变量）和操作数据的函数是分开的
  • 代码复用主要靠函数和宏
  • 没有“类”“继承”“多态”“模板”这些概念
  • 写起来直接、直白，你完全知道机器在干什么

C++ 多范式（Multi-Paradigm）

  • 面向过程：你完全可以像写 C 一样写 C++
  • 面向对象：类、封装、继承、多态
  • 泛型编程：模板、STL 容器与算法
  • 函数式风格：lambda、<algorithm> 里的算法组合
  • 你可以按问题挑选合适的风格，而不是被一种风格绑死

面向对象的三大特性，简单说就是

  • 封装：把数据和操作它的函数打包进 class，用 private 挡住外部乱改。
  • 继承：class Dog : public Animal，复用父类的共性，扩展自己的个性。
  • 多态：同一个 speak() 调用，狗叫“汪”、猫叫“喵”。C 里想做到这点，通常得靠函数指针表，写起来啰嗦又容易错。

泛型：写一次，适配多种类型

/* C：用宏“假装”泛型——只是文本替换，没有类型检查 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int m = MAX(3, 5);          /* 能用，但如果传进来指针/表达式，很容易踩坑 */


// C++：真正的模板，编译期按类型生成代码，类型安全
template <typename T>
T max_of(T a, T b) { return a > b ? a : b; }

int    x = max_of(3, 5);        // T 推导为 int
double y = max_of(1.5, 2.5);    // T 推导为 double
std::string z = max_of(std::string("a"), std::string("b"));
初学者常问：C++ 写的代码是不是就一定“面向对象”？

不是。C++ 允许你写纯过程式代码，也允许写纯泛型代码。 面向对象只是它提供的一种可选工具，用不用取决于问题本身。

代码示例：两个 Hello World

C 版本（面向过程，靠标准库函数 printf）：

/* hello.c —— C 的 Hello World */
#include <stdio.h>          /* 引入 printf 的声明 */

int main(void) {             /* void 表示不接收参数 */
    printf("Hello, World!\n");
    return 0;                /* 返回 0 表示正常结束 */
}

gcc hello.c -o hello && ./hello

C++ 版本（用 std::string 和流式输出 std::cout）：

// hello.cpp —— C++ 的 Hello World
#include <iostream>        // 输入输出流
#include <string>          // std::string

int main() {
    std::string name = "World";              // 自动管理内存的字符串
    std::cout << "Hello, " << name << std::endl;  // 不用写格式串
    return 0;
}

g++ -std=c++17 hello.cpp -o hello && ./hello

代码示例：C 的结构体 vs C++ 的类

同样是“学生”这个概念，C 把数据和打印函数分开写：

/* C：结构体只装数据，操作靠外部函数——数据和逻辑是分开的 */
#include <stdio.h>
#include <string.h>

struct Student {                 /* 只能装数据成员 */
    char name[32];
    int  age;
};

/* 操作数据的函数必须写在结构体外面，靠参数把数据传进来 */
void student_print(const struct Student *s) {
    printf("%s (%d)\n", s->name, s->age);
}

int main(void) {
    struct Student s;               /* 注意：C 里通常要写 struct 关键字 */
    strcpy(s.name, "小明");          /* 字符串只能靠函数拷贝，还要小心越界 */
    s.age = 18;
    student_print(&s);
    return 0;
}

C++ 用 class 把数据和行为封在一起，还能在构造时保证对象一定合法：

// C++：类把数据和行为封装在一起，可以控制访问权限
#include <iostream>
#include <string>
#include <utility>

class Student {
public:
    // 构造函数：创建对象时自动调用，保证对象一出生就是合法状态
    Student(std::string name, int age)
        : name_(std::move(name)), age_(age) {}

    // 成员函数：直接访问自己的数据，不用把对象当参数传来传去
    void print() const {
        std::cout << name_ << " (" << age_ << ")\n";
    }

    int age() const { return age_; }   // 只读访问接口

private:                              // 外部无法直接改，只能通过接口
    std::string name_;
    int         age_;
};

int main() {
    Student s("小明", 18);            // 不用再写 struct 关键字
    s.print();
    return 0;
}
小结

C 的 struct 只是“把几个变量捆在一起”； C++ 的 class 是“把数据 + 操作 + 访问规则 + 生命周期”打包成一个概念。 这就是抽象层次的差别。

04 · 内存管理：手动挡 vs 半自动挡（甚至自动挡）

C 把内存完全交给你：申请、使用、释放都得自己来，写对了非常高效， 写错了就是内存泄漏、段错误、双重释放。C++ 保留了这套手动能力， 但额外提供了“自动回收”的工具，让这类错误在正常代码里几乎消失。

表 3：内存管理对比
对比点C（malloc / free）C++（new / delete 及智能指针）
分配 / 释放malloc / free，成对出现new / delete（数组用 new[] / delete[]）
返回值void*，需要强制类型转换直接返回对应类型的指针，无需强转
大小计算自己写 sizeof 算字节数编译器按类型自动计算
是否调用构造/析构都不会，只是拿到一块原始内存都会，new 调用构造函数，delete 调用析构函数
分配失败返回 NULL，必须自己检查默认抛 std::bad_alloc 异常
常见错误忘记 free、重复 free、越界、悬垂指针裸 new 仍需手动 delete，但可用智能指针规避
现代推荐做法谁申请谁释放，配套写 init / destroy 函数优先用 std::vector、std::string、unique_ptr，几乎不写裸 new

代码示例：C 的 malloc / free

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    /* 1) 自己算字节数；2) 返回值是 void*，要强转；3) 必须检查是否失败 */
    int *arr = (int *)malloc(5 * sizeof(int));
    if (arr == NULL) {
        fprintf(stderr, "内存分配失败\n");
        return 1;
    }

    for (int i = 0; i < 5; ++i) {
        arr[i] = i * i;
    }
    printf("%d\n", arr[4]);

    free(arr);          /* 必须自己记得释放，漏掉就泄漏 */
    arr = NULL;         /* 好习惯：置空，避免悬垂指针 */
    return 0;
}

代码示例：C++ 的 new / delete 与智能指针

#include <iostream>
#include <memory>
#include <vector>

class Widget {
public:
    Widget()  { std::cout << "构造 Widget\n"; }
    ~Widget() { std::cout << "析构 Widget\n"; }
};

int main() {
    // 1) new / delete：分配并调用构造函数，释放前调用析构函数
    Widget *w = new Widget();
    delete w;                    // 必须配对，否则析构函数不会执行

    // 2) 数组要用 new[] / delete[] 配对，混用是未定义行为
    int *arr = new int[5]{1, 2, 3, 4, 5};
    delete[] arr;

    // 3) 现代 C++ 首选：智能指针，离开作用域自动释放
    auto sp = std::make_unique<Widget>();
    sp->doSomething();          // 自动释放，异常安全

    // 4) 栈上的对象：离开作用域自动析构，这就是 RAII
    {
        Widget local;             // 进入作用域：构造
    }                             // 离开作用域：析构，无需任何手写释放代码

    // 5) 容器帮你管内存，扩容、释放都不用操心
    std::vector<int> v{1, 2, 3};
    v.push_back(4);

    return 0;
}   // sp 在这里自动 delete
新手最容易踩的坑
  • new[] 分配的内存必须用 delete[] 释放，不能写 delete。
  • malloc 出来的内存不能用 delete 释放，new 出来的也不能用 free——混用是未定义行为。
  • C 里忘了检查 malloc 是否返回 NULL，程序在内存紧张时会直接崩。
  • C++ 里“裸 new 忘了 delete”依然会泄漏，所以能用智能指针就别用裸指针。

RAII：C++ 内存管理的核心思想

RAII 全称“资源获取即初始化”（Resource Acquisition Is Initialization）， 翻译成人话就是：把资源的生命周期绑在对象的生命周期上。 构造函数里拿到资源，析构函数里释放资源。只要对象能被正确销毁 （栈对象离开作用域、智能指针超出范围、容器被清空），资源就一定会被释放， 哪怕中途抛了异常也一样。

这套思路不只用于内存：文件句柄、互斥锁、socket、数据库连接都可以用 RAII 包装。 C 里要达成同样的效果，通常得在每个 return / goto 分支前手写清理代码，一不小心就漏。

05 · 标准库：一把工具 vs 一整间车间

C 的标准库：小而够用

C 标准库（libc）主要是一批函数，特点是“薄、快、无隐藏开销”：

  • <stdio.h>：printf、scanf、fopen、fread
  • <stdlib.h>：malloc、free、atoi、qsort、rand
  • <string.h>：strcpy、strlen、memcpy、strcmp
  • <math.h>、<time.h>、<ctype.h>、<assert.h>

注意：C 的动态数组、哈希表、字符串类都没有。想要就得自己写， 或者引入第三方库。这也是 C 项目里到处是手写数据结构的根本原因。

C++ 的标准库：STL 是重头戏

C++ 标准库 = C 标准库（兼容部分）+ 一整套基于模板的组件。核心是 STL：

表 4：STL 主要组成部分
类别代表组件作用
容器vector、array、deque、list、map、unordered_map、set、stack、queue动态数组、链表、红黑树、哈希表等常用数据结构，自动管理内存
迭代器begin() / end()、iterator统一的遍历方式，让算法与容器解耦
算法sort、find、find_if、count、transform、accumulate、for_each不用自己写排序查找，直接组合使用
字符串std::string、std::string_view自动扩容、可直接比较与拼接
输入输出iostream、fstream、sstream类型安全的流式 IO，支持自定义类型
智能指针unique_ptr、shared_ptr、weak_ptr自动释放堆内存
并发与工具thread、mutex、atomic、chrono、filesystem、optional、variant线程、时间、路径、可选值等现代设施

同一个任务：把一组数字排序，两者的写法差异很直观。

/* C：qsort 需要自己写比较函数，还要传元素大小和个数 */
#include <stdlib.h>
#include <stdio.h>

int cmp_int(const void *a, const void *b) {
    return (*(const int *)a) - (*(const int *)b);
}

int main(void) {
    int a[] = {5, 2, 8, 1, 9};
    int n = sizeof(a) / sizeof(a[0]);
    qsort(a, n, sizeof(int), cmp_int);
    for (int i = 0; i < n; ++i) printf("%d ", a[i]);
    return 0;
}
// C++：容器 + 算法 + lambda，表达意图而不是实现细节
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> v{5, 2, 8, 1, 9};

    std::sort(v.begin(), v.end());                  // 不用手写比较函数

    // 甚至可以一行指定排序规则
    std::sort(v.begin(), v.end(),
              [](int a, int b) { return a > b; });   // 从大到小

    for (int x : v) {                            // 范围 for，遍历更省心
        std::cout << x << ' ';
    }
    return 0;
}
关于“零开销抽象”

STL 里的一切都是模板，在编译期就确定类型并生成代码， 运行时基本没有额外的解释或动态查找开销（除虚函数、哈希等本身的成本外）。 这就是 C++ 常说的“你不用为没用到的东西付出代价，用到的也不会比手写慢”。

06 · 编译与兼容性：C++ 不是 C 的超集

编译流程基本相同

两者都遵循经典的四步流程，这也是它们能高效、能跨平台的原因：

  1. 预处理：展开 #include、替换宏、处理条件编译。
  2. 编译：把源码翻译成汇编（含语法检查、优化）。
  3. 汇编：汇编代码变成目标文件 .o / .obj。
  4. 链接：把多个目标文件和库合成可执行文件。

常用命令也很像：C 用 gcc hello.c -o hello， C++ 用 g++ -std=c++17 hello.cpp -o hello。 另外 gcc 也能编 C++，只是需要显式链接 C++ 标准库（-lstdc++）， 所以实践中 C++ 项目直接用 g++ 更省事。

“大部分 C 代码可以被 C++ 编译器编译”——但只是大部分

常听到“C 是 C++ 的子集”，严格来说这是近似说法。 绝大多数合法的 C 代码确实能不加修改地用 C++ 编译，但存在一批明确的不兼容点：

表 5：常见的 C / C++ 不兼容点
不兼容点C 的写法C++ 的要求
void* 隐式转换 int *p = malloc(n); 可以直接赋值 必须强转：int *p = (int*)malloc(n);，否则编译报错
关键字冲突 class、new、delete、this、bool、template、try、namespace 等可以当变量名 这些都是保留字，用作标识符会报错
函数声明 int f(); 表示“参数未指定” int f(); 表示“不接收参数”，要写 int f(void); 才等效
字符串字面量 "abc" 类型是 char[]，可赋给 char* 类型是 const char[]，赋给 char* 在 C++11 起被禁止
字符常量 'a' 的类型是 int 'a' 的类型是 char
结构体标签 必须写 struct Foo f;（除非 typedef） 可以直接写 Foo f;
C 独有特性 变长数组 VLA、restrict、_Generic、_Atomic、复合字面量、部分指定初始化 标准 C++ 不支持或支持方式不同，直接编译会失败
函数名修饰 符号名基本就是函数名（add） 会做名字修饰（name mangling，如 _Z3addii），因为要支持重载

混合编程：extern "C"

正因为 C++ 会改写函数名，如果想让 C 代码调用 C++ 写的函数（或反过来）， 就必须用 extern "C" 告诉编译器“这个名字按 C 的规则来”： 

// mylib.h —— 一份头文件同时给 C 和 C++ 使用
#ifdef __cplusplus
extern "C" {              // C++ 编译器看到这段，就关掉名字修饰
#endif

int add(int a, int b);    // 用 C 的调用约定导出

#ifdef __cplusplus
}
#endif

反过来，C++ 调用 C 库（比如 zlib、SQLite、OpenSSL）通常只需要包含头文件即可， 因为这些库的头文件本身已经做了 extern "C" 处理。

结论

“C++ 兼容 C”是一种高度兼容但不绝对的关系。 绝大多数 C 代码能直接编译通过，但涉及关键字、void* 转换、C 特有语法的部分需要小幅修改。

07 · 适用场景：没有最好，只有最合适

C 更适合这些场景

  • 操作系统内核与驱动：Linux 内核、Windows 内核、各类驱动
  • 嵌入式 / 单片机 / RTOS：资源极小，没有 C++ 运行时的空间
  • 实时系统：需要可预测的执行时间，不希望有隐藏的构造/析构开销
  • 需要稳定 ABI 的基础库：libc、zlib、SQLite、OpenSSL
  • 跨语言调用的底层接口：几乎每种语言都能调用 C
  • 教学与打基础：指针、内存、编译链接这些概念在 C 里最直观

C++ 更适合这些场景

  • 游戏引擎与图形渲染：Unreal Engine、各类 3D 引擎
  • 音视频与图像处理：编解码器、实时滤镜、计算机视觉
  • 数据库与中间件：MySQL、MongoDB、Redis 的部分模块
  • 浏览器与虚拟机：Chromium、V8、LLVM
  • 金融高频交易：既要极致性能，又要复杂业务抽象
  • 桌面应用与 CAD：需要大量 UI、模块化和复杂数据结构
  • 大型长期项目：多人协作时，类、命名空间、STL 能显著降低维护成本

现实项目里两者经常共存：底层用 C 写、上层用 C++ 组织； 或者核心算法用 C++ 写，通过 extern "C" 暴露给其他语言。 学 C++ 的同时理解 C，会让你对“程序到底怎么跑起来”有更扎实的认识。

08 · 总结与学习建议

把全文压缩成一句话：C 给你对机器的完全控制，C++ 在保留这份控制的同时，给了你抽象的工具。

给初学者的学习路径建议

  1. 先用 C 打好地基：变量与类型、指针与数组、结构体、函数与递归、 编译链接过程、malloc/free、调试（gdb / 断点 / 看内存）。 这些概念在 C 里最赤裸，学明白了受用终身。
  2. 再过渡到 C++：先学“带类的 C”部分——类、构造析构、封装、引用、 函数重载；然后学继承与多态（virtual、虚析构）； 再学模板与 STL 容器算法。
  3. 重点掌握现代 C++ 的几条纪律： 尽量不写裸 new/delete；优先 vector / string / 智能指针； 用 const 表达意图；理解值语义与移动语义（std::move）； 知道什么是未定义行为。
  4. 动手比看书重要：把本文的示例都敲一遍、改一改、让它报错， 再看编译器的错误信息——这是最快的学习方式。
最后一句

不要问“C 和 C++ 哪个更好”，要问“我手上的这个问题， 更需要贴近硬件的控制力，还是更需要大型代码的组织能力”。 答案不同，选择就不同——而这两门语言，都值得你花时间去理解。
